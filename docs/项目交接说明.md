## 2. 账号与凭证（🔥 最高优先级）

> 这些是 gitignore 的、只在特定机器/账号上，一旦丢失机器人即失联或无人可维护。

### 2.1 钉钉应用归属（最大风险 — ⚠️ 交接时点尚未转移）

- 现状：应用由**实习个人账号**在钉钉开发者后台创建，公司给权限、邀请进组织。
- 影响评估：应用挂在**公司组织**名下，服务运行时用的是 ClientID/ClientSecret，**不依赖个人登录态**——短期离职不会立即断连。
- 真正的坑：**个人账号被回收后，没人能进开发者后台**——无法改配置、加权限、看日志、重新发布版本。
- ✅ **交接动作（离职前必须完成）**：
  1. 找公司管理员，在钉钉开发者后台将**应用负责人/管理员**转移或授权给公司管理员账号；
  2. **当面验证**公司管理员能在后台看到并操作「恩特小助手」应用（不是口头答应，要登录看）；
  3. 把 ClientID / ClientSecret 备份，并写清在后台哪个位置能重新获取。

## 3. 双环境运行说明

### 3.1 测试版（本机，当前唯一运行实例）

- 位置：这台电脑，`D:\ENTAR_AGENT\`
- 启动（v1.13.2 稳定入口，二选一）：
  ```bash
  python -m scripts.main     # 稳定调用入口（推荐）
  python scripts/main.py     # 兼容旧方式
  ```
  → Web 管理层：<http://localhost:8000> 自动跳转 `/admin`（普通用户只用钉钉，Web 无用户层，见 §6 坑 12）
  → 钉钉搜索「恩特小助手」单聊使用
- 交接要点：机器保留，需明确**谁接管这台机器的运维**（开机、重启服务、看日志 `logs/`）。
- ⚠️ 本机运行的坑：**息屏/睡眠会断开钉钉连接**，需保持常亮或迁服务器。
- 生产安全项（v1.13.1）：生产环境必须配置 `ADMIN_PASSWORD`，否则应用拒启；开发环境保留显式兼容行为。

**配置入口：/admin「系统设置」**（新增，无需改代码）
- 侧边栏「⚙️ 系统设置」可填：LLM 模型名与 Key、钉钉 ClientID/Secret、管理后台密码、MinerU Token、通讯录敏感字段 staff_id、识图模型与 Key。敏感项只回显掩码（前 6……后 4），留空 = 保留原值。
- **DeepSeek LLM 模型三选一**（系统设置里「大语言模型名」）：
  | 模型名 | 定位 | 看图 |
  |--------|------|:---:|
  | `deepseek-v4-flash` | 轻量快速版（1M 上下文，纯文本） | ❌ |
  | `deepseek-v4-pro` | 旗舰版（1M 上下文，纯文本） | ❌ |
  | `deepseek-v4-flash-vision-exp` | 实验版视觉模型（纯文本能力≈flash） | ✅ 唯一能看图 |
- **识图联动**（改代码已就位，配置时理解即可）：`大语言模型名` 选了上面带 ✅ 的 vision 模型后，识图**自动复用主模型**（用 DeepSeek Key 调 DeepSeek 端点，请求关思考防正文被吃空），**不再走下面的「识图模型」**（qwen3.7-flash + 阿里云百炼 Key 可留空）；反之选了 flash/pro，识图照旧走专门的识图模型。判断标准 = 模型名是否含 `vision`。
- 保存到 `data/admin_config.json`（gitignore，不进版本库）；`scripts/local_config.py` 原文件不被修改，保留注释与兜底。
- 读取优先级：**环境变量 > 网页填的 > `local_config.py`**。

**怎么重启生效**（改完配置后）
1. 切回运行服务的终端窗口，按 `Ctrl + C` 停掉服务（看到 KeyboardInterrupt 提示，等退干净）；
2. 重新启动：
   ```bash
   python -m scripts.main
   ```
3. 刷新 `/admin`「系统设置」，看掩码是否已变成新值，确认生效。
- 只有「管理后台密码」保存后**立即生效**；其余密钥/模型名**重启服务后生效**（各模块启动时读一次配置）。
- 以后迁服务器 / Docker 同理：`docker compose -f deploy/docker-compose.yml restart`（或 `systemctl restart entar`），停掉再起即可。

## 6. 已知坑清单（隐性知识，必须口头带一遍）

> 这些坑写在 CLAUDE.md「已知问题/注意事项」里，但交接时务必**当面讲一遍**，接手人最容易踩：

1. **息屏/睡眠断连**：服务跑在本机，电脑一息屏钉钉就断，需保持常亮或迁服务器。
2. **Windows 控制台 GBK**：日志无法输出 emoji，日志用纯文本符号。
3. **`reply_markdown()`** **不能** **`await`**：钉钉 SDK 的 reply\_\* 是同步方法，写代码时别加 await。
4. **单进程锁**：v1.2.6 版本替换锁只保证单进程一致，多 worker/多容器前需共享锁或活动版本指针。
5. **停用文件别乱动**：
   - 审核流程已停用（v1.10.2），代码保留注释（`queue_review_for_upload`），恢复时取消注释即可；
   - `tools/search_standards.py`、`tools/search_experience_kb.py` 已停用（v1.11.5 起由 `kb_search` 替代），v1.13.2 起**被自动发现机制明确排除**，文件保留归档，别改回旧签名。
6. **`data/standards/mineru_output/`（185MB+）**：OCR 中间产物，已 gitignore，重入库用 `sync_mineru.py`。
7. **运行时数据不进 git**：`knowledge_base/`、`user_store.db`、`uploads/`、`logs/` 都是自动生成，迁移要整包拷。
8. **看板口语操作只在「看板上下文」生效**（v1.12.9）：「帮我停掉这个」这类口语指代，只有用户在看板对话中（看板词面/有 pending/600s 内聊过看板）才会被 LLM 兜底分类；**冷启动用户的口语操作仍需明说「看板」或用既有命令**。
9. **agent.py 零工具幻觉护栏有盲区**（v1.12.9 记录，TODO 待办）：LLM **零工具调用**直接编造「将停用」时不触发纠偏护栏——现有护栏只拦「声称已执行 + 有工具记录」场景。
10. **测试隔离与禁读**（v1.13.1/1.13.2）：单元测试默认用 `data/_test_runtime/`、**不读真实 `scripts/local_config.py`**；未显式 mock 的 DeepSeek 请求会被测试模式阻断——写回归测试时别依赖真实凭据。
11. **生产 fail-closed**（v1.13.1）：生产环境未配置 `ADMIN_PASSWORD` 时应用拒绝启动、`/admin` 拒绝访问。
12. **Web 用户层已砍**（v1.12.8）：`/ask`、`/feedback` 路由物理删除，`/` 302 跳 `/admin`，`web_page.py` 停用归档——**普通用户只用钉钉单聊**；恢复方式见 `main.py` 文件头 docstring。
13. **历史回放只回放最近一次**（v1.12.7 已知限制）：「看上次的看板」只取最近一次留档；翻更早（`看板历史 N`）留待后续。
14. **A2 僵尸订阅删除待确认**（v1.12.6 遗留）：绑定已删光静态键的订阅（`project_status`/`test_issues`）会导致每日重复推送，直接删库需用户确认，交接前可处理。
15. **系统设置重启才生效**（新增）：/admin「系统设置」保存后，除「管理后台密码」立即生效外，其余密钥需**重启服务**（§3.1 有操作步骤）；判断是否生效看保存后的提示文字（「重启后生效」还是「立即生效」）。敏感项网页只回显掩码，忘密码只能在 `local_config.py` 找回明文。
