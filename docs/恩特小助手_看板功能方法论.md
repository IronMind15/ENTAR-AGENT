# 恩特小助手 — 每日项目看板自动推送方法论文

> 供 ENTAR_AGENT 设计 Agent 参考。本文聚焦工作流程与设计模式，具体数据源参数以示例形式说明，实际值由配置管理。

---

## 一、功能概述

管理者在钉钉单聊中对恩特小助手说一次"帮我每日推送项目看板"，小助手设置定时任务，之后每天自动执行以下工作流：

1. 从钉钉 AI表格拉取多个数据源的当前状态（各数据源由不同人员在线维护）
2. 组装 Markdown 看板
3. 通过机器人主动推送给指定人员

数据源由各业务人员各自维护更新，小助手每次执行时实时拉取最新值，不需要任何人手动触发。

## 三、数据采集工作流

### 3.1 AI表格查询模式（核心模式）

所有 AI表格数据源遵循同一套采集模式，区别仅在于 Base ID、Table ID、字段映射表不同。

**采集步骤：**

1. **列出分表**（如数据源有多个按周/月命名的分表）
   - 调用 AI表格 API 列出 Base 下所有数据表
   - 从返回的 `tableName` 中用正则提取数字，取最大值作为最新分表
   - 如果数据源只有固定单表，跳过此步

2. **查询记录**
   - 用上一步得到的 Table ID（或固定 Table ID）查询记录
   - 处理分页：`hasMore=true` 时用 `nextToken` 继续请求直到取完

3. **提取字段**
   - 遍历每条记录的 `cells`（或 `fields`）字典
   - 用字段映射表（fieldId → 业务含义）提取各字段值
   - 用通用解析器处理不同类型的单元格值

**示例——研发项目现况表采集：**

```yaml
数据源名称: 研发项目现况表
Base ID: "np9zOoBVBYQe06entLExnXArW1DK0g6l"  # 示例值，实际从配置读取
分表模式: 按周命名，需自动检测最新周次
  分表命名规律: "{N}周"（如"33周""32周"）
  检测方法: 正则提取数字，取最大值
  示例: ["33周","32周","31周"...] → 选"33周"
字段映射:
  "01ZM8y7": {含义: 项目名称, 类型: list[dict], 取值: "[0].name，多个用 / 连接"}
  "7qnPz0F": {含义: 阶段,     类型: dict,      取值: ".name"}
  "YQnOvE5": {含义: 状态,     类型: dict,      取值: ".name"}
  "FjrTLFt": {含义: 产品型号,  type: string,    取值: 直接取}
  "aepzDFy": {含义: 本周进展,  type: string,    取值: 直接取，含换行}
  "uWD6X8E": {含义: 风险卡点,  type: string,    取值: 直接取，含换行}
```

**示例——测试问题表采集：**

```yaml
数据源名称: 整机下线测试问题
Base ID: "ndMj49yWjXjmOQmxIReylDeeJ3pmz5aA"  # 示例值
分表模式: 无，固定单表
Table ID: "atLkTeV"  # 示例值
字段映射:
  "Hr3tyzt": {含义: 状态, type: dict, 取值: ".name"}
  "GuqYscv": {含义: SN,  type: string, 取值: 直接取}
  "ChZTtyj": {含义: 描述, type: string, 取值: 取前100字}
```

> **设计要点**：字段映射表应放在配置文件中，不硬编码在代码里。新增数据源时只需新增一段配置 + 一组字段映射，采集逻辑通用。

### 3.2 文件类数据源采集模式

如果某个数据源是 xlsx 文件而非 AI表格（如生产日报），采集方式不同：

**采集步骤：**

1. **获取文件**（三种方式之一）
   - 接收模式：发送者把文件发到恩特小助手单聊，`file_handler.py` 自动保存
   - 群聊模式：恩特小助手在发送者所在群，Stream 连接自动接收群内文件
   - 云盘模式：文件存于钉钉云盘共享目录，用云盘 API 列出+下载

2. **解析 Excel**
   - 用 openpyxl `data_only=True` 加载（读缓存计算值，不读公式）
   - 定位数据行/列（通过固定位置或标签名匹配）
   - 提取最新日期对应的数据

**示例——生产日报解析：**

```yaml
文件名规律: "生产日报{YYMMDD}.xlsx"
Sheet结构:
  汇总表（第1个sheet）:
    日期行: 第2行，C9列起为日期列（Excel序列号或datetime）
    数据行: 每个工序占连续4-5行（计划/实际/不良数/良率）
    定位策略: 从C9向右扫描最后一个非空列 = 最新日期列
  每日sheet（按日期命名如"8月6号"）:
    组装异常: R14 C2
    当日处理: R37 C1
    次日计划: R39 C1
    定位策略: 固定行号（不依赖中文标签，避免WPS编码问题）
```

> **设计要点**：Excel 解析的行号、列号、Sheet 命名规律也应放配置。不同格式的日报只需换一段配置，解析逻辑通用。推荐长期将文件类数据源迁移为 AI表格，统一采集模式。

### 3.3 单元格值通用解析器

AI表格单元格值有多种类型，必须统一处理。以下函数覆盖所有已知类型：

```python
def extract_cell_value(cell) -> str:
    """统一解析 AI表格单元格值，返回字符串

    处理类型：
    - None / 空字符串 → ""
    - str → 直接返回
    - dict（单选/状态字段）→ 取 name 或 text
    - list[dict]（多选/多关联字段）→ 各项 name 用 " / " 连接
    """
    if not cell:
        return ""
    if isinstance(cell, str):
        return cell
    if isinstance(cell, dict):
        return cell.get("name", cell.get("text", str(cell)))
    if isinstance(cell, list):
        parts = []
        for item in cell:
            if isinstance(item, dict):
                parts.append(item.get("name", item.get("text", str(item))))
            else:
                parts.append(str(item))
        return " / ".join(parts)
    return str(cell)
```

### 3.4 周次分表自动检测

```python
def find_latest_week_table(tables: list[dict]) -> dict | None:
    """从分表列表中找数字最大的周次

    示例输入: [{"tableId":"a","tableName":"33周"}, {"tableId":"b","tableName":"32周"}]
    示例输出: {"tableId":"a","tableName":"33周"}
    """
    max_num, latest = 0, None
    for t in tables:
        match = re.search(r'(\d+)', t.get("tableName", ""))
        if match:
            n = int(match.group(1))
            if n > max_num:
                max_num, latest = n, t
    return latest
```

## 四、数据解析与统计工作流

### 4.1 项目现况数据解析

采集到原始记录后，转换为业务结构：

```yaml
输入: AI表格原始记录列表
输出: 项目列表，每项含:
  - name: 项目名称（字符串）
  - stage: 阶段（字符串）
  - status: 状态（字符串，"正常"/"滞后"等）
  - model: 产品型号（字符串）
  - progress: 本周进展（字符串，可能需截断到约200字）
  - risk: 风险及卡点（字符串）
处理逻辑:
  1. 遍历每条记录的 cells
  2. 用字段映射表 + extract_cell_value 提取各字段
  3. 如有多项目名称，用 " / " 连接
```

### 4.2 测试问题统计

```yaml
输入: AI表格原始记录列表
输出:
  - total: 总记录数
  - status_counts: 状态→数量的字典
  - faulty_sns: 状态为"故障"的SN列表
  - pending_verify: 状态为"待验证"的SN+描述列表
处理逻辑:
  1. 遍历记录，用 extract_cell_value 提取状态字段
  2. 按 status_counts[status] += 1 统计
  3. 状态="故障"的记录，SN 加入 faulty_sns
  4. 状态="待验证"的记录，SN+描述前100字加入 pending_verify
```

> **设计要点**：哪些状态算"需关注"（如故障、待验证）也应放配置，不同场景可能关注不同状态。

### 4.3 生产日报数据解析

```yaml
输入: xlsx 文件路径
输出:
  - date: 报表日期
  - 各工序的 计划/实际/不良数/良率
  - assembly_issues: 组装异常说明
  - processing_results: 当日生产外处理结果
  - next_day_plan: 次日生产计划
处理逻辑:
  1. openpyxl 加载（data_only=True）
  2. 汇总表：扫描最后一列有日期的列，取各工序行数据
  3. 每日sheet：按固定行号提取异常说明、处理结果、次日计划
  4. 良率小数转百分比；#DIV/0! 转为"无数据"
  5. Excel日期序列号转 datetime（基准1899-12-30 + 序列号天数）
```

## 五、Markdown 组装工作流

### 5.1 排序规则

- 项目按状态排序：关注状态（如"滞后"）排在前面，正常状态排在后面
- 同状态内可按优先级或名称排序
- 哪些状态排前面 → 配置化

### 5.2 组装模板

看板包含 N 个板块（板块数 = 数据源数），每个板块对应一个数据源。以下为三板块示例：

```markdown
# {看板标题}

> 数据日期：{日期}（第{周次}周）

---

## 一、{板块1标题}

### {关注状态分类}（{数量}个）

**1. {名称}** | {属性1}：{值1} | {属性2}：{值2}
- {属性3}：{值3}
- {属性4}：{值4（截断到约200字）}
- {属性5}：{值5}

（重复每个项目）

---

## 二、{板块2标题}

### 状态统计（共{总数}台）

{状态1}{数量1} / {状态2}{数量2} / ...

### {关注状态1}（{数量}台）

{SN1}、{SN2}、...

{主要问题类型描述}

### {关注状态2}（{数量}台）

- {SN1}：{描述}
- ...

---

## 三、{板块3标题}（{日期}）

### {子板块1}

{属性1}：计划{值} / 实际{值} / 不良{值} / 良率{值}

### {子板块2}

{内容}

### {子板块3}

{内容}

---

[{链接文本}]({看板URL})
```

### 5.3 格式约束

- 钉钉机器人 Markdown 不支持表格语法（`|---|`），用文本列表格式
- 总字符数控制在 5000 以内
- 长文本字段截断到约 200 字
- 良率等数值需格式化（小数→百分比）
- 错误值（如 `#DIV/0!`）转为"无数据"

### 7.2 AI表格客户端设计模式

仿照 `contact_api.py` 的 `DingTalkContactClient` 模式构建，关键设计点：

```yaml
认证:
  方式: 新版 API token（oauth2/accessToken）
  复用: 与 DingTalkNotifier 相同的 token 获取逻辑，建议抽取公共 token 管理器
  缓存: 进程内缓存 + threading.Lock，提前60秒刷新

HTTP Session:
  trust_env: False（与 contact_api.py 一致，避免代理劫持）

方法:
  list_tables(base_id) → list[dict]:
    GET /v1.0/aitable/{baseId}/tables
    返回 [{"tableId":"...","tableName":"..."}]
  
  query_all_records(base_id, table_id, max_records=100) → list[dict]:
    GET /v1.0/aitable/{baseId}/tables/{tableId}/records?maxRecords={N}&nextToken={cursor}
    自动分页：hasMore=true 时用 nextToken 继续
    返回 records 列表，每条含 cells/fields 字段

错误处理:
  重试: 3次指数退避（0.5s/1s/1.5s）
  429/5xx: 重试
  4xx: 不重试，直接报错
```

### 7.3 工具注册模式

利用项目已有的 `@register` 装饰器体系：

```yaml
工具1: query_dashboard_data
  职责: 采集所有数据源，返回 JSON
  触发词: 看板、推送看板、项目看板、每日看板
  参数: 无（所有配置从 config 读取）
  返回: JSON 字符串，含各数据源解析后的结构化数据

工具2: push_dashboard
  职责: 组装 Markdown + 调用推送
  触发词: 推送给老板、发给某人、每日推送
  参数: user_ids（可选，不传则用默认配置）
  返回: 推送结果 JSON
  依赖: 先调用 query_dashboard_data 获取数据
```

在 `tools/__init__.py` 末尾追加自动导入即可注册。

### 7.4 配置设计

所有数据源参数放配置文件，不硬编码：

```yaml
数据源配置结构:
  数据源1:
    name: 研发项目现况表
    base_id: "xxx"        # AI表格 Base ID
    table_mode: "latest_week"  # 或 "fixed"
    table_id: ""           # fixed 模式时填，latest_week 模式留空
    field_map:
      "fieldId1": {label: "项目名称", type: "list_name"}
      "fieldId2": {label: "阶段", type: "dict_name"}
      ...
  
  数据源2:
    name: 测试问题
    base_id: "xxx"
    table_mode: "fixed"
    table_id: "xxx"
    field_map:
      "fieldId1": {label: "状态", type: "dict_name"}
      ...
    status_groups:           # 状态分组统计
      attention: ["故障", "待验证"]   # 需关注的的状态
      normal: ["已完成", "已打包"]    # 正常状态
  
  数据源3（如为文件类型）:
    name: 生产日报
    type: "xlsx"             # 或 "aitable"
    file_pattern: "生产日报*.xlsx"
    file_dir: "data/daily_reports/"
    sheet_structure:
      summary_sheet: 0       # 汇总表位置
      date_row: 2            # 日期行号
      date_start_col: 9     # 日期起始列
     工序行映射: {工序名: {计划: 行号, 实际: 行号, ...}}
      daily_sheet_pattern: "X月X号"
      daily_fields:
        assembly_issues: {row: 14, col: 2}
        processing_results: {row: 37, col: 1}
        next_day_plan: {row: 39, col: 1}

推送配置:
  push_targets: ["userId1"]  # 推送目标
  push_hour: 9
  push_minute: 0
  kanban_url: "https://..."
  title: "恩特能源每日项目看板"
```

> **设计要点**：新增数据源或修改字段时只改配置，不改代码。配置可存入 SQLite（项目已有的 prompts 表模式可参考），支持后台在线编辑。

### 7.5 System Prompt 追加

在 `prompts/system_prompt.txt` 的能力列表中追加新工具说明即可，格式仿照已有的 search_knowledge_base 等工具。

### 7.6 定时任务

在 `main.py` 用项目已有的 APScheduler 设置 cron 定时任务。定时任务内部直接调用采集→组装→推送逻辑，不经过 LLM Function Calling（定时任务没有用户对话上下文）。

用户对话触发时走 LLM Function Calling 路径：LLM 判断"看板"意图 → 调用 query_dashboard_data → 调用 push_dashboard。

用户说"每天推送"时，LLM 除了推送当次外，还应触发定时任务注册（或在对话中告知用户已设置定时任务）。定时任务配置持久化到 SQLite。

### 7.7 文件接收增强（如使用文件类数据源）

在 `file_handler.py` 保存文件后，检测文件名是否匹配某个数据源的 file_pattern。匹配则复制到该数据源的专用目录，后续推送时读取该目录下最新文件。

```yaml
处理流程:
  1. file_handler 保存文件到 data/uploads/（现有逻辑）
  2. 检测文件名是否匹配配置中的 file_pattern
  3. 匹配则复制到数据源专用目录（如 data/daily_reports/）
  4. 推送时读该目录下 mtime 最大的文件
```

## 九、错误处理策略

| 场景 | 处理 |
|------|------|
| AI表格 API 网络超时 | 重试3次指数退避，仍失败则该板块显示"数据获取失败" |
| AI表格查询返回空 | 该板块显示"暂无数据" |
| 文件类数据源文件不存在 | 该板块显示"今日暂未收到数据" |
| 某字段值为空 | 显示"暂无" |
| 数值字段为 `#DIV/0!` | 显示"无数据" |
| 定时任务整体失败 | 记录日志，不影响次日执行；可选择性通知管理员 |
