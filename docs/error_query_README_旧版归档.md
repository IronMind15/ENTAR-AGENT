# 🔧 故障查询模块 — error_query.py

## 一句话

> **工程师输入错误码或故障描述 → 返回原因 + 排查建议**

---

## 系统全景

这个模块是整个恩特小助手的**第一个技能**，也是三步走计划的第一步。整个链路涉及 4 个文件：

```
data/                        scripts/                        输出
┌──────────────┐            ┌──────────────────────┐      ┌──────────┐
│ Excel 数据源  │  sync_kb   │  Chroma 向量知识库     │      │ Web 页面  │
│ 故障代码表    │ ────────→ │  knowledge_base/     │      │ localhost │
│ (手工维护)    │            │ (自动管理)            │      │          │
└──────────────┘            └──────────┬───────────┘      │ 钉钉     │
                                       │                   │ (未来)   │
                          error_query  ▼                   └──────────┘
                          .handle(q) ────→ DeepSeek API
                                           生成答案
```

---

## 数据流（按步骤）

### 准备工作：Excel → 知识库

```bash
python scripts/sync_kb.py
```

这一步把 `data/` 目录下的 Excel 表格**同步到 Chroma 向量数据库**。Excel 的格式要求：

| 第一列 | 第二列 | 第三列 |
|--------|--------|--------|
| 错误码 | 故障原因 | 排查建议 |
| 002    | 过压保护 | 检查输入电压... |

同步脚本会自动比对：新错误码自动加、已有但内容变了的会询问是否更新、完全一样的跳过。

### 运行时：查一次走三步

当用户输入一个问题（比如「002」或「过压了怎么办」），`error_query.handle(q)` 内部走三条路：

```
用户输入 "002"
     │
     ▼
┌──────────────────┐
│ 第一步：精确匹配   │ ← collection.get(where={"error_code": "002"})
│ 查 error_code     │
│ 是否完全等于输入   │
└──────┬───────────┘
       │
  匹配到了？──── 是 ──→ 直接把这笔记录当上下文
       │
       否
       ▼
┌──────────────────┐
│ 第二步：语义搜索   │ ← collection.query(query_texts=["002"])
│ 用向量相似度找    │    找最像的 2 条
│ 最相关的内容      │
└──────┬───────────┘
       │
  有结果？────── 是 ──→ 把 2 条记录拼一起当上下文
       │
       否
       ▼
┌──────────────────┐
│ 返回：没找到       │
│ 提示用 Excel 补充  │
└──────────────────┘
       │
       ▼
┌──────────────────────────────────────┐
│ 第三步：AI 生成答案                   │
│ 上下文 + 用户问题 → DeepSeek API      │
│ DeepSeek 按格式输出：                 │
│   1. 错误类型                         │
│   2. 可能原因                         │
│   3. 排查步骤                         │
└──────────────────────────────────────┘
       │
       ▼
  返回 {"answer": "...", "source": "..."}
```

## 三种使用方式

### 1️⃣ Web 页面（最简单）

```bash
python scripts/main.py
```

然后打开 http://localhost:8000 ，输入错误码直接查。

### 2️⃣ HTTP API

```bash
curl "http://localhost:8000/ask?q=002"
```

返回 JSON：

```json
{
  "answer": "1. 错误类型：过压保护...\n2. 可能原因：...\n\n---\n📎 参考来源：\n【002】过压保护",
  "source": "【002】过压保护"
}
```

### 3️⃣ Python 直接调用

```python
from skills.error_query import handle

result = handle("002")
print(result["answer"])
```

## 模块内部结构

```
error_query.py
│
├── 模块级初始化（首次导入时运行一次）
│   ├── 读取 local_config.py 拿 API Key
│   ├── 连接 Chroma（knowledge_base/ 目录）
│   └── 加载 BGE 中文嵌入模型
│
├── call_deepseek(prompt)          # 调 DeepSeek API
│   ├── 系统 prompt：你是一位能源设备技术支持工程师
│   ├── 温度 0.3（较稳定，不瞎编）
│   └── 超时 30 秒
│
├── _extract_exact(query)          # 精准匹配
│   └── collection.get(where=...)
│
├── _search_semantic(query)        # 语义搜索
│   └── collection.query(n_results=2)
│
└── handle(query) → dict           # 对外唯一入口
    ├── 输入校验
    ├── 精确匹配 → 语义搜索 → AI 生成
    ├── 来源追踪（判断 AI 真正引用了哪些来源）
    └── 兜底提示（没找到时引导用户补充数据）
```

## 关键设计决策

| 决策 | 为什么 | 后续可能变化 |
|------|--------|------------|
| Chroma 做向量库 | 本地持久化，无需部署数据库服务 | 数据量大后可换 pgvector/Milvus |
| BGE 中文嵌入 | 国产、轻量（30MB）、CPU 可跑 | 需要更高精度可以换 bge-large |
| DeepSeek API | 国产合规、价格低、中文好 | 可以换其他兼容 API（如通义千问） |
| 精确匹配优先 | 错误码是精确标识，先确保确定性匹配 | 不变 |
| 温度 0.3 | 降低幻觉率 | 需要创造性回答时调高 |
