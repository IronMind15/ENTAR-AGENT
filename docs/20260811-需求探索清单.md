## 1️⃣ 会议工作流

**场景痛点**：每周/每月各类会议（SST 固态变压器评审、项目周会等），会前准备资料、会中记录、会后行动项跟踪都是手工劳动，纪要散落在各人手里。

**现有差距**：小助手有识图（发照片/白板/文档）、钉钉文档读取（发链接自动识别概要）、经验库检索，但没有「会议」这条专属链路——无法把会议材料汇总、生成纪要模板、会后自动分派行动项。

**建议方案**（三阶段）：
- ① 会前：发会议材料（PDF/图片/钉钉文档）→ 自动汇总生成「会前材料摘要」（复用 summarize_doc + describe_image）
- ② 会中：发会议纪要文档 → 「帮我整理会议纪要」→ 按「议题/结论/行动项/负责人/截止时间」结构化（LLM 提取）
- ③ 会后：「发会议行动项」→ 生成任务清单，可配合看板追踪

**复用资产**：`summarize_doc` 工具（文档总结）、`describe_image`（白板/照片识图）、DingTalkNotifier 主动推送、经验库 RAG。

**排期**：P1。① 先做（纯复用），② 需加「会议纪要模板」prompt，③ 与看板结合。

## 2️⃣ 经验库（第二步核心）

**场景痛点**：研发/制造工程师遇到重复问题（IGBT 过温、通信故障、现场调试坑），老员工的经验只在口头/微信里，新人重复踩坑。胡总三步走计划第二步即此。

**现有差距**：经验库 RAG 已搭建（五段式模板：故障现象→排查步骤→根因→解决方案→验证结果），但**内容几乎为空**——只有示例条目，实际经验没沉淀入口；提交流程藏在审核链路里，员工不知道怎么写。

**建议方案**：
- ① 低门槛提交：员工发文本/截图 → 「保存为经验」→ 自动套五段式模板结构化（LLM 填充，缺的字段提示补）
- ② 图片经验：发现场照片/故障截图 → 识图描述 + 提问引导 → 生成经验条目（复用 describe_image）
- ③ 检索体验：搜经验时按「次数/相关度」排序，回答带「贡献人 + 验证状态」

**复用资产**：`experience_kb` collection、`search_experience_kb` 工具、上传直接学习链路（v1.10.2）、五段式模板。

**排期**：P0-P1（第二步主线）。① 直接可做；② 与识图工具联动；③ 依赖经验数据积累。

## 3️⃣ 识图能力深化

**场景痛点**：员工发设备照片、接线图、铭牌、报警截图，希望小助手「看懂 + 告诉下一步」，而不只是描述图片内容。

**现有差距**：v1.10.0 已实现发图自动识别（qwen3.7-flash 视觉），但识别结果只「描述」，没有接后续动作——不能追问、不能入库、不能关联故障/经验/标准。

**建议方案**：
- ① 识图后追问链路：图片描述进会话记忆 → 用户可连续追问「这个报警对应哪个故障码」→ LLM 检索故障库回答（关键缺口：图片描述未写 memory，需对齐 v1.11.3 卡片写 memory 做法）
- ② 报警截图联动：识别出的文字（报警代码）自动走故障精确匹配快速通道
- ③ 图转经验：接经验库（见组 2）

**复用资产**：`describe_image` 工具、`file_handler` 图片保存、故障代码快速通道、memory。

**排期**：P1。① 优先（改动小，补写 memory 即可打通追问）。

## 4️⃣ 每日看板多视图

**场景痛点**：老板/PMO 要「一眼看到今天有什么变化、哪些项目滞后」；不同角色想看的角度不同（PMO 看进度、总监看风险、技术主管看技术问题）。现在看板 LLM 单次调用组装，质量不稳定、看不到细节。

**现有差距**：v1.11.0 看板已支持动态源 + 定时推送；但只有一种组装模板，无内容级变化展示，无角色模板。

**建议方案**：
- ① 角色模板预设 3 个：PMO 项目助理（默认）/ 项目总监 / 技术主管（订阅加 role 字段）
- ② 内容级变化：「📌 今日变化」小节（昨天 vs 今天 diff，需快照存完整 items）
- ③ LLM 多阶段组装：角色提示词 + 分阶段整理（详见 TODO「每日看板 LLM 多阶段工作流」，已排期）

**复用资产**：看板子系统（采集/组装/订阅/推送）、summarize_doc、DingTalkNotifier。

**排期**：P1（已排期，见 TODO.md P2 项）。

## 5️⃣ 权限与可信身份（v2.0）

**场景痛点**：五中心（PMO/研发/制造/商业/运营）各有独立资料与保密要求；老板担心「员工能查到不该看的内容」。现在 Web 端用户名可伪造，知识库检索无中心隔离。

**现有差距**：`center_config` 已配五中心；`find_employee` 有敏感字段权限判断；但 Web 登录/SSO 未落地，Chroma 无 dept_knowledge collection，上传/查询无部门隔离。

**建议方案**：
- ① 钉钉可信身份：员工在钉钉内直接使用天然可信（sender_id），Web 端加登录（对接钉钉扫码）
- ② 中心隔离：新增 `dept_knowledge` collection，chunk 带 center/department metadata，检索按归属中心过滤
- ③ 文档权限：公共区所有中心可见，部门区仅本中心 + 管理员

**复用资产**：center_config、user_store（SQLite 用户/会话/权限）、工具 contextvar 隔离模式。

**排期**：P1-P2（并入 v2.0 企业知识中枢）。

## 6️⃣ 检索质量与评估闭环

**场景痛点**：员工搜标准/经验，中英文混用、术语口语化，常搜不到；故障代码短关键词效果不稳。

**现有差距**：混合检索（BM25+向量+重排）已上线，但有 4 个已知缺口——BM25 缓存永不失效、rerank 开关未落地、跨语言检索失败（中文查英文标准）、评估集失真（详见 TODO「RAG 检索改进」）。

**建议方案**：
- ① 优先修 BM25 缓存失效（新文档入库后混合检索还是旧索引，与上传学习直接冲突）
- ② 英文标准入库时补中文别名/摘要元数据后重索引（跨语言真缺口）
- ③ rerank 加配置开关默认关（轻量环境省 1.1GB 内存）
- ④ 评估集修正后跑 eval_rag 建基线

**复用资产**：enhanced_search、eval_rag.py、RAG 基线评估集。

**排期**：P1（已排期 2026-08-11，路由意图 + 钉钉文档读取之后）。

## 7️⃣ 钉钉生态打通

**场景痛点**：员工工作都在钉钉里（审批、待办、日程、群聊），希望小助手不止单聊——能进群、能代建待办/审批、能推日程。

**现有差距**：目前仅单聊（搜索「恩特小助手」），群聊未开放；钉钉文档读取/推送已打通，但审批/待办/日程接口未接。

**建议方案**：
- ① 群聊能力评估：先解决身份/权限/信息泄露边界（谁 @ 就响应谁、敏感检索不出群）
- ② 钉钉审批/待办接口：经验提交走审批、行动项转待办（需管理员开通对应 API 权限）
- ③ 钉钉知识库对接：企业自有钉钉文档库批量接入（先调研权限范围/同步周期/上传规范）

**复用资产**：钉钉文档客户端（dingtalk_doc_client）、DingTalkNotifier 推送、Stream 模式长连接。

**排期**：P2（依赖组 5 权限落地后开放群聊）。

## 8️⃣ 运维与数据质量

**场景痛点**：老板/管理员想知道「知识库有多少内容、哪个文档没人用、MinerU 额度烧了多少、系统是否健康」，现在要翻日志。

**现有差距**：有 sync_tracker（同步状态追踪）、task_manager（后台任务）、logs/；但没有面向管理员的健康面板和主动告警。

**建议方案**：
- ① 数据资产面板：各 collection 块数/来源/最近更新/检索频次（复用 Chroma 统计）
- ② 主动告警：同步失败、MinerU 额度接近上限、DeepSeek 调用异常 → 钉钉推给管理员（复用 DingTalkNotifier）
- ③ 用量统计：LLM/API 成本周报

**复用资产**：sync_tracker、task_manager、DingTalkNotifier、Chroma。

**排期**：P3。管理员真实用起来后可排。

## 9️⃣ 第三步 — AI 辅助研发（远期）

**场景痛点**：研发在做技术调研/方案评审/文档编写时，资料查找（标准/PCB/经验）分散，评审意见靠人肉汇总。

**现有差距**：标准库 + PCB 计算器已就绪，但没有面向研发场景的专属流程（调研报告、评审清单、文档生成）。

**建议方案**：
- ① 技术调研助手：输入课题 → 检索标准 + 经验库 → 生成调研报告框架（复用 search_standards + search_experience_kb）
- ② 方案评审辅助：上传方案文档 → 对照标准条款逐条核查（复用标准 RAG）
- ③ 文档自动生成：设计说明/测试记录 → 模板化生成

**复用资产**：标准知识库、PCB 计算器、summarize_doc、经验库。

**排期**：第三步（第一步走稳后再启动）。
