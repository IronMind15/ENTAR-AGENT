# 恩特小助手 工具板块化重构建议

> 日期：2026-08-13 ｜ 性质：设计建议（未实现，待主模型理解后按此修改） ｜ 版本号：由用户拍板后写入
> 背景：用户提出借鉴钉钉开放平台「scope 权限聚合」模型——第一层按板块分组（知识库/看板/计算…），第二层按具体功能（知识库：创建/删除/学习/重学/更新/读取；看板：创建/删除/修改/查询…），希望恩特小助手不再「工具一大堆平铺罗列」。

---

## 一、现状盘点：不是工具太多，而是三套机制割裂

当前功能入口分三套并行机制，互相不对齐：

### 机制 A — LLM 工具注册中心（10 个平铺，LLM 只见这一层）

位置：`scripts/tools/__init__.py`（导入）+ 各 `tools/*.py`（`@register`）

| 隐式板块 | 工具名 | 确认策略（policy） |
|---|---|---|
| 知识库 | search_knowledge_base（读取） | 只读直行 |
| 知识库 | create_knowledge_base（创建） | confirm |
| 文件 | manage_uploaded_file（删除/重学，action 枚举） | confirm |
| 计算 | calc_pcb_trace / calc_copper_busbar | 只读直行 |
| 看板 | query_dashboard（查询）/ push_dashboard（推送） | 推送 confirm |
| 同事 | find_employee | 只读直行（敏感字段按审核人白名单） |
| 识图 | describe_image | 只读直行 |
| 文档 | summarize_doc（总结，可选外发） | 外发时 confirm |

### 机制 B — 钉钉 bot 正则命令（不走 LLM，秒回）

位置：`scripts/skills/dingtalk_bot.py`（_process_text 内逐条正则）

- 文件板块：`帮我学习`、`把这个文档学到XX`、`我的文件`、`删除学习N`、`重新学习N`、入库确认词、`ENTARBOSS` 管理员模式/退出/查看全部文件
- 审核残留（已停用但仍拦截）：`同意同步/拒绝同步` 前缀（dingtalk_bot.py:484-489 + knowledge_review.py）
- 看板板块：全部走 `parse_subscription_command`（见下），不在 bot 正则里

### 机制 C — 技能层（5 个按 priority 平铺）

位置：`scripts/skills/__init__.py:72-76`

error_query(100) → pcb_calc(90) → dashboard(80) → standards_query(70) → agent(50 兜底)

### 关键发现

1. **看板板块已经是「二级结构」**：`scripts/dashboard/subscription_commands.py` 的 `parse_subscription_command` 已解析出 12 种意图——`stop / resume / delete / query / set_self / change_recipients / change_time / change_freq / create / doc_create` + 模板 4 种（describe_template / submit_template / set_template / choose_template）。用户设想的「看板板块：创建/删除/修改/查询」**已实现**，只是藏在技能层、未纳入统一能力清单。
2. **`manage_uploaded_file` 是「工具内 action 枚举」的既有雏形**（action: delete|relearn），可参考其成败再决定是否推广。
3. **`scripts/prompts/system_prompt.txt` 已滞后**：手写编号只覆盖 7 个工具，describe_image / summarize_doc / manage_uploaded_file 已注册但未写入说明。
4. **同功能多入口**：「删除」类操作有 bot 正则 + LLM 工具两个入口，行为需保持一致。

## 二、认知修正：钉钉 scope 模型不能照搬到 LLM 工具层

- 钉钉开放平台的本质是 **scope 聚合**：一个权限点 = 一组 API（读文档权限 = 名称/内容/时间/操作者）。它是给「人/应用」做**授权粒度**。
- LLM function calling 是**扁平数组**：模型靠 name + description 选工具，**不感知分组**。
- ❌ **不要做「两级代理工具」**（一个板块一个工具 + action 枚举全部子功能）：
  - DeepSeek 对嵌套枚举参数解析不稳，一次调用叠加两个选择维度容易填错；
  - 一次只能执行一个动作，并行多工具能力退化；
  - confirm 粒度被板块级确认模糊（看板创建与看板删除不应共用确认文案）；
  - `manage_uploaded_file` 经验：action 枚举随功能膨胀会越写越重。
- ✅ 钉钉模型真正值得借鉴的两个维度：
  1. **能力聚合**（按板块组织命名与文档，解决观感与可维护性）；
  2. **按板块授权**（读/写/管理粒度 + 部门/角色过滤，对标 scope 的价值核心）。

## 三、推荐方案：三层落地

### 第 1 层：命名空间化 + 板块化 prompt（低成本，立即见效）

工具改名带板块前缀（LLM 零负担，只是名字；日志/调试/观感立刻清晰）：

| 板块 | 建议工具名 | 现状 |
|---|---|---|
| 知识库 | `kb_search`（原 search_knowledge_base）、`kb_create`（原 create_knowledge_base）、`kb_file_manage`（原 manage_uploaded_file） | 改名 |
| 计算 | `calc_pcb_trace`、`calc_copper_busbar` | 保留 |
| 看板 | `dash_query`（原 query_dashboard）、`dash_push`（原 push_dashboard） | 改名 |
| 同事 | `contact_find`（原 find_employee） | 改名 |
| 识图 | `image_describe`（原 describe_image） | 改名 |
| 文档 | `doc_summarize`（原 summarize_doc） | 改名 |

同步修改：
- `scripts/prompts/system_prompt.txt`：按板块组织（知识库 / 计算 / 看板 / 同事信息 / 识图 / 文档），补全 3 个漏写的工具说明，每板块写明确认规则；
- `scripts/skills/agent.py` 的 `_TOOL_DISPLAY` 流式显示映射同步改名；
- 测试中所有断言工具名的用例同步（全量回归兜底）。

### 第 2 层：统一能力清单（核心工程，解决三套割裂）

新建一份「能力清单」（建议放 `scripts/tools/capability_registry.md` 或直接落成一份 JSON/常量，供文档与测试引用），字段：

```
板块 → 功能 → 入口（LLM 工具 / bot 命令 / 技能）→ 确认策略（policy）→ 权限（预留）→ 状态（启用/停用/残留）
```

要求：
1. **看板订阅 12 种意图全部登记**（它们目前只在 `subscription_commands.py` 内部可见）；
2. **bot 的 20+ 正则命令全部登记**（含「帮我学习/我的文件/管理员模式」等）；
3. LLM 工具与 bot 命令从同一份清单对齐，消灭「同功能多实现」；
4. 审核残留（`同意/拒绝同步`）在清单中标记为「残留-待清理」，同时清理 `dingtalk_bot.py:484-489` 的拦截。

### 第 3 层：板块级权限（对标钉钉 scope，长期）

- 现有 `policy`（`scripts/tools/__init__.py` 的 confirm/risk 机制）扩展为板块策略：`kb` 板块按 department 过滤（`kb_registry.get_visible_knowledge_bases` 雏形已有）、`dash` 板块按 owner 隔离（订阅表已有）、`calc` 板块全员只读；
- `ENTARBOSS` 管理员模式未来可升级为「按板块授权」而非全局开关；
- 此层与「部门权限/SSO 可信身份」（CLAUDE.md P1 待办）一起做，不单独开工。

## 四、落地顺序与工作量估计

| 步骤 | 内容 | 工作量 | 风险 |
|---|---|---|---|
| 1 | 第 1 层：改名 + prompt 板块化 + 测试同步 | 约半天 | 低（全量回归兜底） |
| 2 | 第 2 层：能力清单建立 + 三套机制登记对齐 | 1~2 天 | 中（涉及 bot 与技能层） |
| 3 | 清理审核残留命令（第 2 层附带） | 0.5 天 | 低（已停用功能） |
| 4 | 第 3 层：板块级权限 | 与部门权限一起排期 | 中（权限语义变更需评审） |

注意事项：
- 看板订阅命令**保持 bot 正则秒回**是有意设计（v1.11.13 确认词双闸防误判、秒回不耗 LLM），只进能力清单、不工具化；
- 工具改名是公开接口变更，需同步 `system_prompt.txt`、`agent.py` 显示映射、全部测试断言、CHANGELOG 对应条目；
- 建议每次改完跑 `python -m unittest discover tests -v`（当前 706 项基线）确认无回归。

## 五、验收标准

1. `get_tool_names()` 输出均为「板块_功能」命名，无平铺感；
2. `system_prompt.txt` 按板块组织且覆盖全部注册工具（无遗漏）；
3. 能力清单覆盖：10 个 LLM 工具 + 看板 12 意图 + bot 20+ 命令，无未登记入口；
4. 钉钉全流程冒烟：知识库创建/学习/查询、看板创建/订阅/推送、PCB 计算、同事查询均正常；
5. 全量回归 706 项全绿（含改名后工具名断言）；
6. CHANGELOG 记录本次重构（版本号由用户拍板）。
