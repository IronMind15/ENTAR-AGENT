## 一、综合结论（一句话）

**恩特把「眼睛（上下文）和手脚（工具）」做得很好，缺的是「不做错事」的那一圈安全网（约束+验证+纠正），以及把 RAG/记忆每一层做成可度量的科学迭代。**

- 单 Agent + RAG + 工具主线上，恩特与两本书第 2/3/4 章高度重合，且实现质量扎实
- 真正的差距集中在：**上下文工程**、**Agent 层评估**、**检索/记忆侧增强**、**Agent 循环韧性**

## 二、5 大差距（两本书交叉共识，按优先级排序）

### 🔴 差距 1：上下文工程没做 —— 最紧急
- **hello-agents ch9**：GSSC 流水线（Gather-Select-Structure-Compress），token 预算内按「相关性×权重 + 新近性×权重」贪心选择，`reserve_ratio` 保护系统指令
- **ai-agent-book ch2**：KV Cache 三条铁律——动态信息**追加到消息末尾**，别拼进 system prompt
- **恩特现状**：[agent.py:243-289](scripts/skills/agent.py#L243-L289) 把用户档案+短记忆+长记忆全拼进 system prompt，无预算、无缓存友好
- **痛点**：恩特天天讲「省 token、秒回」，但每轮前缀全变 = DeepSeek 前缀缓存零命中
- **落地**：改造 [agent.py](scripts/skills/agent.py) 的 system prompt 组装段 —— 动态内容改 `messages.append` 到消息末尾 + 加 `build_system_context()` 预算函数（参考 hello-agents `code/chapter9/context/builder.py`）

### 🔴 差距 2：Agent 层评估缺失 —— 最系统
- **hello-agents ch12**：BFCL（工具调用 AST 匹配校验「函数名+参数」）+ LLM Judge / Win Rate
- **ai-agent-book ch6**：Rubric 四准则（必要/重要/可选项 + 幻觉一票否决）+ LLM-as-a-Judge + Pass@k vs Pass^k
- **恩特现状**：166 项 unittest 全是函数级；[eval_rag.py](scripts/eval_rag.py) 只测**检索层**（Recall/MRR），不测「Agent 循环选对工具、填对参数、答对问题」
- **风险**：改一条工具 description / 换模型后，回答质量变没变**无法量化**
- **落地**：新建 `scripts/eval_agent.py` + `data/eval/agent_eval.json`（真实问法 + 期望工具名/参数 + 期望答案要点），用 DeepSeek 当 judge 按 Rubric 打分。接上 TODO P2「检索评测」已有基础

### 🟠 差距 3：检索侧增强 —— 两条互补的路
| 方法 | 出自 | 改哪侧 | 对恩特价值 |
|------|------|--------|-----------|
| **MQE/HyDE** 查询扩展 | hello-agents ch8 §8.3.5 | 查询侧 | 口语问法召回 +30~50% |
| **Contextual Retrieval** 上下文前缀 | ai-agent-book ch3 实验3-11 | 索引侧 | 4278 标准切块补「出自哪份标准哪一节」锚定，检索失败率降 49% |

- **恩特现状**：[enhanced_search.py](scripts/skills/enhanced_search.py) 混合检索（BM25+RRF k=60+rerank）已达标，但查询侧原样、标准块是「孤儿块」
- **落地**：
  - MQE：`enhanced_query()` 加 `enable_mqe=True` 参数，LLM 生成 3-4 个等价查询合并检索（兼容现有降级策略，LLM 失败退回原查询）
  - Contextual Retrieval：`doc_mgr/engine.py` 的 `_prepare_chunks` 里，对 standards 块用已有 `_extract_std_info()` 生成前缀 `[来源：GB/T 34133-2023 第6.2条] + chunk` 再入库

### 🟠 差距 4：Agent 循环韧性 —— 防死循环、防重复搜索
- **ai-agent-book ch2**：Agent 状态栏（注入「第 N/5 轮、已调工具 X 次、上一轮未命中建议换关键词」）+ 重复调用指纹检测（同 `(name, params)` ≥3 次跳出）
- **hello-agents ch4**：Reflection 反思回路（工具结果不相关→改写查询重试）
- **恩特现状**：[agent.py](scripts/skills/agent.py) 只有 `MAX_AGENT_LOOPS=5` 硬上限，「搜不到→反复搜同一词→白烧 token」
- **落地**：for 循环每轮在 messages 末尾追加 `{"role":"user","content":"<agent_status>..."}`；`_execute_tool` 前做指纹缓存

### 🟠 差距 5：记忆升级 —— 从「堆 facts」到「能覆盖、能忘」
- **ai-agent-book ch3**：Mem0 冲突覆盖（同字段 ADD/UPDATE/DELETE）——用户改口/纠错时旧 fact 覆盖
- **hello-agents ch8**：importance 评分 + forget 遗忘策略（容量/时间淘汰）
- **恩特现状**：[memory_compress.py](scripts/skills/memory_compress.py) LLM 压缩 facts/summary，但无评分、无冲突处理
- **落地**：压缩提示词让 LLM 输出 `importance`；保存前查同 user 同主题 fact 做「最新覆盖旧版」；`format_long_term` 按 importance 排序截断

## 四、落地路线（按成本/收益排序）

```
【第 1 步 · 纯工程小改，立刻见效】—— 对应差距 1 + 4
  ├─ 上下文工程：动态内容移出 system prompt + token 预算
  ├─ Agent 状态栏 + 重复调用检测（防白烧 token）
  └─ 改动文件：scripts/skills/agent.py（L243-289 段 + for 循环）

【第 2 步 · 一次性索引成本】—— 对应差距 3
  ├─ 标准分块补上下文前缀（Contextual Retrieval）
  ├─ 查询侧 MQE 开关（默认关，轻量环境不增开销）
  └─ 改动文件：scripts/doc_mgr/engine.py + scripts/skills/enhanced_search.py

【第 3 步 · 持续投入、回报最高】—— 对应差距 2 + 5
  ├─ eval_agent.py 回答层评估（Rubric + LLM Judge）
  ├─ 记忆冲突覆盖 + importance 排序
  └─ 改动文件：scripts/eval_agent.py（新建）+ scripts/skills/memory_compress.py
  └─ 正好接上三步走「经验知识库」目标
```
