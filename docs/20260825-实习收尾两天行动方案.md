## 🗓️ Day 1（08-26）— 代码与验证日

### 🔧 任务 1：补齐「零工具幻觉护栏」将来时盲区 ⭐ 最优先代码活

**为什么**：TODO.md「Agent 零工具幻觉护栏盲区」记录的日志实证（2026-08-14 袁会荧）：用户说「帮我停掉这个」落 Agent → LLM **零工具调用**直接编造「**将停用**」——现有护栏 `_FAKE_EXEC_DONE_RE` 只认「已XXX / ✅已」**完成态**，**将来时承诺漏网**（v1.12.6 修过完成态，这个是范围外残留）。

**改动点**：`scripts/skills/agent.py`
- `_FAKE_EXEC_DONE_RE`（L75-78）：现匹配完成态。
- 新增 `_FAKE_EXEC_FUTURE_RE`，匹配**将来时/意向承诺** + 写操作动词，例如：
  ```python
  _FAKE_EXEC_FUTURE_RE = re.compile(
      r"(?:将|马上|即将|稍后)[^。！？\n]{0,6}?(?:停用|删除|取消|修改|调整|推送|发送|"
      r"开通|恢复|创建|停止|更新|添加|移出|移除)")
  ```
  （不要用孤立的「会」字，配合写操作动词才安全。）
- `_needs_fake_exec_correction`（L96-120）：把判定条件从
  `if not _FAKE_EXEC_DONE_RE.search(content): return False`
  改为完成态 **或** 将来时承诺命中即进入后续判定；后续 `has_instruction`（`_ACTION_VERB_RE` 含「停掉/停用/停止」）+ `has_emphasis_done` 两道闸**保持不变**——将来时承诺必须配上「用户下了执行/确认指令」才纠偏，防止复述历史/正常聊天误伤。

**补测试**：`tests/test_agent_fake_exec.py` 新增 2~3 条
- ✅「帮我停掉这个」+ 回答「好的，将停用该看板。」+ 零写工具 → **纠偏**
- ✅「确认修改」+ 回答「将为您调整订阅。」+ 零写工具 → **纠偏**
- ✅ 正常查询「查一下XX」+ 回答「我会帮您查看。」→ **不纠偏**（查询非写动词）

**验收**：
1. `python -m unittest tests.test_agent_fake_exec -v` 全绿（含新增）
2. 全量 `python -m unittest discover -s tests -p "test_*.py"` → **1022 项全绿**（基线不变，新增后应 ≥1022）

> ⚠️ 红线：只改 `_needs_fake_exec_correction` 判定 + 新增正则，**不要**动 `_ACTION_VERB_RE` / `_ACTION_CONFIRM_RE` / `_FAKE_EXEC_CORRECTION` 文案——它们是 v1.12.6 已验收行为，动一处可能引发回归。

### 🧪 任务 3：真机关键链路快验（防实测翻车最实在的一步）

**为什么**：接手人/同事实测翻车，大多不是代码 bug，而是**没验证过的链路**没跑通。把已验证边界写清楚，接手人就知道哪些被验证过、哪些没有。

**做法**：用**测试用户/测试文档/测试看板任务**，对照交接文档 §5 验收标准逐项真机走一遍：

- [ ] 故障查询：问 `d4-1` → 秒回
- [ ] 语义搜索：问「逆变器报错」→ 命中
- [ ] 上传学习链路：发文件 → 「帮我学习」→ 入库 → 「我的文件」→ 删除学习
- [ ] 看板全链路：发文档 → 「做每日看板」→ 确认 → 「查看看板」→ 「停用」→ 「删除」
- [ ] 识图：发图片 → 自动识别
- [ ] `/admin` 系统设置：掩码回显、重启生效、管理后台密码立即生效

**产出**：在交接文档 §5 验收标准逐项勾 ✓（验证过）/ ✗（未验证），并注明测试用的假数据。

> ⚠️ 红线：全部用**测试数据**，绝不触碰正式 `knowledge_base/`、`user_store.db` 里的真实业务记录。
